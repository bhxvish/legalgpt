### Counterfactual test: paired result (complete, 147 fact patterns)

| | LLM alone (direct) | LLM + Prolog rules (pipeline) |
|---|---|---|
| accuracy | 92% | 95% |
| a one-fact flip changes the verdict correctly | 95% | 100% |
| an omitted element gives INSUFFICIENT | 77% | 85% |
| same verdict for a paraphrase | 100% | 95% |
| unsafe errors (wrong definite verdict) | 6% | 5% |

**Paired test.** 8 cases are right only with the rules and 3 only without them. Exact McNemar
p = 0.23, so the gain is a trend, not significant at this n. The rules' clearest effect is on the
cases they are built for: flips (100%) and omissions (85% vs 77%).

**Provenance.** The model is qwen3.8-27b. 144 pipeline answers came from Groq. 3 came from
OpenRouter's Cerebras host (fp16) when the Groq free tier ran out, and each is marked `via`. Without
them the result is identical (n = 144, same p).

### Reading section 1

- **Same model, with and without LegalGPT** (gpt-5.4-mini, gemini-3.5-flash-lite, gpt-oss-120b):
  - **Punishment.** Inside LegalGPT, all three models stated a wrong punishment in 0 of 40
    punishment questions. Closed-book, the rate was 18% [9–32] for gpt-5.4-mini and Gemini, and
    55% [40–69] for gpt-oss-120b.
  - **Out-of-scope.** Closed-book, 47–90% of the civil questions were answered as IPC offences.
    Inside LegalGPT, 0% [0–11].
- **Section identification:** LegalGPT scored 82%. The closed-book models scored 73–80%, with
  overlapping intervals, so this is not a demonstrated gain for those two. gpt-oss-120b, at 40%
  closed-book, did gain.
- **Retrieval, not the model, decides section and scenario accuracy inside LegalGPT.** In 359 of
  360 cases (120 questions × 3 models), an answer scored correct exactly when the gold section was
  among the retrieved sources. The models differ mainly in how often they decline: answers beginning
  "I don't know" numbered 31 for gpt-oss-120b, 34 for gpt-5.4-mini and 57 for Gemini.
- **Lenient vs strict scoring.** A refusal that goes on to name the retrieved sections ("I don't
  know … the sources cover section 415") counts as a hit in the table. Not counting those
  answers:

  | LegalGPT with | right section, table → strict | scenario, table → strict |
  |---|---|---|
  | gpt-oss-120b | 82% → 82% | 45% → 43% |
  | gpt-5.4-mini | 82% → 82% | 45% → 37% |
  | gemini-3.5-flash-lite | 82% → 78% | 43% → 22% |

  Closed-book models never refuse, so their numbers are unchanged.
- **Scenarios: the closed-book models do better** (78–85% vs 22–45%). LegalGPT answers only
  from retrieved sections. Better scenario retrieval is the main open problem, since retrieval sets
  the ceiling.
- **Cost** (measured from the providers' token counts):
  - gpt-5.4-mini ($0.75 / $4.50 per million input / output tokens): $0.117 for 150 LegalGPT
    answers and $0.162 for 150 closed-book answers. Grounded answers are shorter: 9.4k output
    tokens vs 34.6k.
  - gpt-oss-120b, remaining answers via OpenRouter ($0.15 / $0.60): $0.103 for 150 LegalGPT and 73
    closed-book answers.
  - Gemini ran on the free tier.
- **gpt-oss-120b provenance.** The first 77 closed-book answers came straight from Groq. The other
  73, and all 150 LegalGPT answers, came through OpenRouter, pinned to Groq as host with no
  fallback (`--route Groq --cache-as`). This is the same model on the same host. Rows record the
  route in `via`.
- **Citation markers** (`run_baselines.py recite`):
  - gpt-oss writes citations as `【1】` or `[1†L2-L4]`. The chat app canonicalizes these to `[1]`
    (`app/core/citations.py`), but the benchmark runner did not, so 69 of 150 gpt-oss LegalGPT
    answers had their citations ignored.
  - With the app's canonicalization applied (sources re-derived by the local, deterministic
    retriever), gpt-oss-120b's right-section score went from 32% to 82%. Its other metrics did not
    change.
  - No other run had such markers.
- **Model names:** `gemini-2.5-flash` is closed to new API keys (HTTP 404), so
  `gemini-3.5-flash-lite` was used. GitHub Models was retired by GitHub on 30 July 2026.

### Notes on method

- **Same sample for every system:** 40 punishment and 20 definition questions, 60 test scenarios
  and 30 out-of-scope questions (seed 7).
- **Closed-book prompt:** "You are a helpful legal assistant for Indian law… cite it by section
  number". LegalGPT gets the app's legal prompt with retrieved sources. LegalGPT's `[n]` citations
  count as citing that source's section.
- **gpt-oss-20b:** at its default reasoning effort it returned an empty answer to 6 of 13
  questions, because it spends the whole output budget (4,096 tokens) on hidden reasoning. It is
  therefore run at **low reasoning effort** (`@low`). The default-effort answers are kept as
  `_discarded_…bak`.
- **Scorer:** bugs found by reading real answers were fixed before reporting: Unicode spaces and
  hyphens ("three years", "120‑B"), digit terms ("3 years"), "life imprisonment",
  and "death" only as a punishment.

### Counterfactual test: label correction after the first run

The first run had 16 omission cases. In three omission types, the remaining sentences imply the
omitted fact:
- s.379 *taken from possession*: the consent sentence names the owner;
- s.279 *endangered safety*: "dangerously high speed, weaving between vehicles";
- s.304A *intent to kill*: "it never occurred to A that someone might die".

Both arms answered those cases "CONSISTENT", which is reasonable. These three elements are now
marked "implied, never omitted" for **every** frame (`app/benchmark/factgen.py`), and the scores
above use the corrected set. Before the correction, the qwen3.8-27b results were:

| arm | n | accuracy | omit correct | unsafe errors |
|---|---|---|---|---|
| direct | 51 | 86% | 62% | 12% |
| pipeline | 51 | 92% | 75% | 8% |

The rules pipeline was ahead before and after the correction. The remaining shared miss is s.379
*without consent*: no sentence states consent either way, and both arms assumed there was none.
